================================================================================
SECURITY COMPLIANCE - LICENSE POLICY
================================================================================

Alert ID: SB-LICENSE-POLICY-VIOLATION::bsd-2-clause
Date: 2026-02-16
Severity: Medium
Repository: https://github.com/Kaleidoscope-Inc/grammes

================================================================================
ISSUE DESCRIPTION
================================================================================

This repository has been flagged for using dependencies with BSD 2-Clause 
"Simplified" License, which violates organizational license policy.

License policy violations can lead to:
- Legal issues and intellectual property rights compromise
- Breach of contractual obligations
- Compliance risks with open-source software usage
- Regulatory non-compliance

================================================================================
COMPLIANCE CONTROLS AFFECTED
================================================================================

1. SOC 2 - CC6.1
   Requirement: Organizations must protect themselves from unauthorized 
   information disclosure, which includes adherence to software licensing 
   agreements.

2. GDPR - Article 32
   Requirement: Requires a level of security appropriate to the risk. 
   Violating software licenses can lead to security vulnerabilities, 
   thereby compromising data protection.

3. NIST SP 800-53 - CM-10
   Requirement: Software Usage Restrictions. The organization uses software 
   and associated documentation in accordance with contract agreements and 
   copyright laws.

4. FedRAMP - CM-10
   Requirement: Software Usage Restrictions. Organizations must use software 
   in accordance with licensing agreements and copyright laws.

5. ISO 27001 - A.8.1.1
   Requirement: Inventory of Assets. Violation of license policy may indicate 
   improper asset management and lack of control over organizational assets.

================================================================================
REMEDIATION ACTIONS IMPLEMENTED
================================================================================

1. Created .license-policy.yaml
   - Documents approved and prohibited licenses
   - Provides policy rationale and compliance mapping
   - Serves as reference for developers

2. Added GitHub Actions Workflow (.github/workflows/license-check.yml)
   - Automatically checks licenses on every PR and push
   - Runs weekly scheduled scans
   - Blocks merges if prohibited licenses are detected
   - Generates license reports as artifacts

3. Created Makefile targets
   - 'make license-check': Check licenses locally before committing
   - 'make license-report': Generate detailed license report
   - Easy integration into development workflow

4. This compliance documentation (SECURITY_COMPLIANCE.txt)
   - Explains the issue and requirements
   - Provides guidance for developers
   - Documents remediation steps

================================================================================
DEVELOPER GUIDELINES
================================================================================

Before adding new dependencies:

1. Check the dependency's license:
   go-licenses check github.com/example/package

2. Verify it's on the approved list in .license-policy.yaml

3. Run local license check:
   make license-check

4. If a dependency has a prohibited license:
   - Find an alternative with an approved license
   - Document the decision in PR description
   - Consult with legal/compliance team if needed
